How IBM can track an invoice purchase

When a buyer picks Invoice, data-popup-webhook-received doesn't fire and the browser only gets the order reference. This page compares two ways for IBM to get the order.

Option 1 (proposed) IBM puts its own cart id in the secure payload tags. Its backend gets order.payment.pending with that tag at Generate Invoice. Its front end asks its own backend. No FastSpring client events used.
Option 1a (Adam's workaround) Browser reads fsc-paymentMethod and the session id from data-popup-event-received, then calls Sessions v2 for the order id. Relies on undocumented event fields.
